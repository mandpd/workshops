## Build

```bash
node flatten.js        # from workshops/ root
```

Reads `decks/*/source/` + `decks/*/source/deck.json`, writes `decks/*/dist/`. Also copies `shared/shared.css` and `shared/shared.js` into each deck's `dist/`.

**Never hand-edit `decks/*/dist/`** — changes will be overwritten on the next flatten.

## Concept folder convention (this deck specifically)

The `coding-with-agents` deck has a third directory: `concept/`. These are self-contained preview HTML files (full `<head>`, inline topnav, direct `initKeyNav` call) used for iteration before a slide is baked into `source/` with partial markers. This is the "Phase 1 — Preview" workflow from the slide-authoring skill, with `concept/` as its conventional home.

When adding a new concept slide, remember to:
1. Update the *previous* concept slide's `initKeyNav` `nextUrl` for arrow-key nav.
2. Update the *previous* concept slide's static `.section-nav` `Next →` button `href`.
3. Add an entry to the previous slide's topnav.

Source/dist slides have their keynav + topnav auto-generated by `flatten.js` from `deck.json` — no manual edits needed there.

## Committing

Decks are checked in; `dist/` is committed (so the deck works when served without running flatten). Commit `source/` changes and the corresponding `dist/` output together.
